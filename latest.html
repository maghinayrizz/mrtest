GLOBAL CUSTOMER SUPPORT: TIPS & TRICKS Issue No. 1

Salesforce: Dev Request Creation

The two reasons requests bounce back — and the quick fixes that stop it.

BOUNCE REASON Not enough info Dev doesn't have enough to act on — the #1 reason requests get sent back.
BOUNCE REASON Weak repro steps Copy-pasted from the case instead of written as steps a developer can actually follow.
THE FIX: GET THESE FIELDS RIGHT
Found in Phase Select the appropriate affected environment on where the customer experienced the issue (Live vs. UAT, not where engineers reproduced it), because it's often misreported and determines how urgently DEV respond.
System Revision It should be filled in accurately with the customer's actual app version (e.g., Platform ERP 9.15.1), since it's often misreported or misunderstood and the version where the issue occurs is critical for triage.
Functional Area Wrong pick = wrong team = delayed triage.
Expected & Actual Results Clearly state what is actually happening, and your best understanding of what is the expected result.
Repro Steps Provide clear, numbered steps a developer can follow to reproduce the issue without production access. Use the DEV Ticket Writer to generate the Repro Steps.
Attachments Show your analysis — database screenshots, error messages, SQL tables. For error messages, don't just capture the error — capture the whole screen, where it happened, and what you did right before it showed up.
Business Impact What's happening now — not what could happen. Put a number on it if possible.
✕"Could stop the customer from invoicing."
✓"Blocking invoicing — $100,000 in lost revenue."
✕"Operations halted. Can't build routes." (copied word-for-word into the Do Nothing Impact field too)
✓"Operations halted — unable to build routes for 30 customers."
ⓘ On Priority: Tag the DEV Request with the priority that matches the AMCS Priority Criteria.
Priority 1
  • All Systems Down
  • Severely degraded business critical process
  • Significant measurable Financial Impact
  • Major Security Risk-in line with AMCS Security Policy (CVSS 10.0)
  • Escalation from SLT
  • No Acceptable Work-Around
Priority 2
  • Degraded business critical process
  • Measurable Financial Impact
  • Data corruption
  • Legislative noncompliance issues
  • Security Risk-in line with AMCS Security Policy (CVSS >9.8)
  • Regardless of if found in UAT or Prod if a defect exists that meets criteria in released version.
Priority 3
  • Any other Bug that doesn't meet P1/P2 criteria
